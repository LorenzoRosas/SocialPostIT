01 Introduzione al Progetto

1.1 Cos'è Social PostIt

Social PostIt è una piattaforma social leggera sviluppata in Node.js, pensata come progetto didattico per esplorare le fondamenta dello sviluppo web full-stack. Permette agli utenti registrati di pubblicare post con testo e immagini, interagire con i contenuti altrui tramite like e commenti, condividere post sui social network e comunicare in tempo reale tramite chat.

L'intera applicazione gira su un unico file server (server.js) e salva tutti i dati su file JSON locali, senza necessità di un database esterno. Le pagine HTML vengono generate dinamicamente dal server usando il motore di template EJS.

ℹ️
Natura del progettoSi tratta di un progetto educativo. Non è progettato per uso in produzione su larga scala: la gestione della sicurezza (password in chiaro, cookie senza httpOnly) è semplificata intenzionalmente.

1.2 Obiettivi e Scopo

  • Dimostrare il funzionamento di un server HTTP con Express in Node.js
  • Illustrare il rendering server-side con template EJS
  • Esplorare la persistenza dati tramite file JSON senza database
  • Implementare autenticazione base tramite cookie
  • Introdurre le comunicazioni real-time con WebSocket
  • Gestire upload di immagini tramite codifica base64

1.3 Funzionalità Principali

03 Registrazione e Login

3.1 Come Registrarsi

Per creare un account clicca su Registrati nella navbar. Inserisci un username unico e una password, poi clicca su "Registra". Il sistema:

  • Verifica che lo username non sia già in uso
  • Salva le credenziali in utenti.json
  • Ti fa accedere automaticamente e ti reindirizza alla home
⚠️
SicurezzaLe password vengono salvate in chiaro in utenti.json. Questo è accettabile per un progetto didattico ma non per un'applicazione reale. In produzione si userebbe hashing con bcrypt.

3.2 Come Accedere

Clicca su Accedi nella navbar. Inserisci username e password. Se le credenziali sono corrette, il server imposta un cookie di sessione nel browser e ti reindirizza alla home. Se le credenziali sono errate, viene mostrato un messaggio di errore rosso: "Credenziali errate".

Il cookie di sessione contiene lo username codificato con encodeURIComponent e ha Path=/, quindi è valido su tutte le pagine del sito. Non ha scadenza impostata (dura fino alla chiusura del browser, salvo clearing manuale).

3.3 Logout

Clicca su Esci nella navbar. Il server invalida il cookie impostando la data di scadenza a gennaio 1970 (data nel passato): il browser lo elimina immediatamente. Dopo il logout vieni reindirizzato alla home come utente non autenticato.

04 Creare un Post

4.1 Form Nuovo Post

Clicca su Nuovo Post nella navbar (visibile solo se sei loggato). Compila:

  • Titolo — campo obbligatorio, appare come intestazione del post
  • Contenuto — corpo del post (testo libero)
  • Immagine — opzionale, si carica tramite il pulsante apposito

Dopo aver cliccato "Pubblica", il post viene salvato in posts.json con: titolo, contenuto, autore (dal cookie), data/ora, array likes vuoto, array comments vuoto.

4.2 Aggiungere un'Immagine

Clicca sull'area tratteggiata "📷 Carica immagine" per aprire il selettore file. Sono accettati solo file di tipo immagine (accept="image/*"). Dopo la selezione:

  • Viene mostrata un'anteprima dell'immagine nella pagina
  • L'immagine viene convertita in base64 (stringa di testo) tramite FileReader
  • La stringa base64 viene inserita in un campo nascosto del form
  • Al submit, viene inviata insieme agli altri dati al server
📦
Come funziona base64Un'immagine PNG/JPEG viene convertita in una lunga stringa di testo che inizia con data:image/png;base64,.... Questo permette di salvare l'immagine direttamente dentro il file JSON senza un sistema di storage separato.

4.3 Limiti e Validazione

  • Dimensione massima immagine: 5 MB — controllata lato client prima dell'invio
  • Il server accetta body fino a 10 MB (configurato in Express)
  • Se l'immagine supera 5 MB, viene mostrato il messaggio "Immagine troppo grande (max 5MB)" e il campo viene resettato
  • Il campo immagine è opzionale: un post senza immagine mostra solo il testo

05 Home Feed e Interazioni

5.1 Visualizzazione Post

La home page (/) mostra tutti i post in ordine dal più recente al più vecchio. Ogni card di post include: titolo, badge autore, data di pubblicazione, immagine (se presente, affiancata al testo), testo del contenuto, pulsante like, contatore commenti, pulsante condivisione, sezione commenti.

Se il post ha un'immagine, questa viene mostrata nella colonna sinistra (45% della larghezza) e il testo nella colonna destra. Su mobile (schermi <640px) la disposizione cambia in verticale (immagine sopra, testo sotto).

5.2 Like

Ogni post ha un pulsante ❤️ con il contatore dei like. Il sistema funziona con AJAX (fetch API): quando clicchi, il browser invia una richiesta POST a /like/:index in background, senza ricaricare la pagina. Il server risponde con JSON contenente il nuovo conteggio e lo stato del like.

  • Se non hai ancora messo like → il tuo username viene aggiunto all'array likes del post
  • Se hai già messo like → il tuo username viene rimosso (toggle)
  • Il pulsante diventa rosso (class="liked") se hai già messo like
  • Se non sei loggato, il pulsante è disabilitato (attributo disabled)

5.3 Commenti

Sotto ogni post c'è una sezione commenti. Se sei loggato, puoi scrivere un commento (max 300 caratteri) nel campo di testo e premere "Invia". Il form invia una richiesta POST a /comment/:index che aggiunge il commento all'array del post e ricarica la pagina. I commenti mostrano: autore, testo, data.

Se non sei loggato, al posto del form appare il link: "Accedi per commentare."

5.4 Condivisione

Il pulsante "🔗 Condividi" apre un menu a comparsa con quattro opzioni:

  • 📱 WhatsApp — su mobile usa la Web Share API nativa; su desktop apre wa.me/?text=...
  • ✈️ Telegram — apre t.me/share/url con titolo e anteprima del testo
  • 🐦 X / Twitter — apre twitter.com/intent/tweet
  • 📋 Copia link — copia negli appunti il testo del post + URL della pagina; mostra una notifica toast "✅ Link copiato!"

Il menu si chiude automaticamente cliccando fuori da esso. Sono aperti al massimo un menu alla volta.

06 Chat Live

6.1 Accedere alla Chat

Clicca su Chat Live nella navbar (pulsante verde, visibile solo se sei loggato). La chat è protetta: se tenti di accedere a /chat senza essere loggato, vieni reindirizzato al login.

Appena apri la pagina, il browser stabilisce una connessione WebSocket con il server. Il server ti invia immediatamente un messaggio di benvenuto privato e notifica tutti gli altri utenti connessi del tuo ingresso.

6.2 Inviare Messaggi

Scrivi un messaggio nel campo di testo in basso e premi il pulsante "Invia" o il tasto Enter (senza Shift). Il messaggio viene inviato a tutti gli utenti connessi in tempo reale tramite WebSocket.

  • I tuoi messaggi appaiono allineati a destra con sfondo azzurro
  • I messaggi degli altri appaiono a sinistra con sfondo grigio
  • I messaggi di sistema (ingresso/uscita utenti) appaiono centrati in giallo corsivo

La chat non conserva la cronologia: i messaggi sono visibili solo agli utenti connessi in quel momento e scompaiono al ricaricamento della pagina.

08 Domande Frequenti (FAQ)

Posso vedere i post senza essere registrato?

Sì. La home page è pubblica. Puoi leggere tutti i post e i commenti senza fare login. Le azioni che richiedono l'autenticazione (like, commenti, post, chat) sono disabilitate o richiedono il redirect al login.

I messaggi della chat vengono salvati?

No. La chat usa WebSocket puro senza persistenza: i messaggi esistono solo in memoria durante la sessione. Se ricarichi la pagina o il server si riavvia, la cronologia è persa.

Posso usare la stessa username su più dispositivi?

Sì, ma l'autenticazione è tramite cookie nel browser. Ogni browser/dispositivo ha il proprio cookie e può fare login indipendentemente con le stesse credenziali.

Cosa succede se carico un'immagine molto grande?

Il controllo lato client blocca immagini sopra 5 MB mostrando un errore. Il server ha un limite di 10 MB per la dimensione totale del body, quindi un'immagine base64 da 5 MB (che occupa ~6.7 MB come stringa) rientra nel limite.

Posso eliminare un post o un commento?

No. La versione attuale non implementa la funzionalità di eliminazione. Per rimuovere dati è necessario modificare manualmente i file utenti.json o posts.json.

Il server funziona su Windows/Mac/Linux?

Sì. L'applicazione usa path.join(__dirname, ...) per costruire i percorsi dei file in modo compatibile con tutti i sistemi operativi, quindi funziona su qualsiasi piattaforma che supporti Node.js.

09 Limitazioni Note

  • Password in chiaro — non c'è hashing. In produzione si userebbe bcrypt o argon2.
  • Cookie non sicuri — il cookie non ha il flag httpOnly né Secure. Può essere letto da JavaScript e inviato su HTTP non cifrato.
  • No HTTPS — il server gira solo su HTTP. In produzione si userebbe HTTPS con un certificato SSL.
  • Nessuna sessione server-side — non c'è invalidazione lato server delle sessioni. Modificare manualmente il cookie consente di impersonare qualsiasi utente.
  • File JSON come database — le operazioni di lettura/scrittura sono sincrone e non gestiscono concorrenza. Su traffico elevato possono verificarsi condizioni di gara (race conditions).
  • Immagini in base64 nel JSON — un'immagine da 5 MB occupa ~6.7 MB come stringa base64 nel file posts.json. Con molti post con immagini, il file può diventare molto grande.
  • Chat senza storia — i messaggi non vengono persistiti, quindi non c'è storico.
  • Nessuna paginazione — tutti i post vengono caricati in una sola richiesta; con molti post, il caricamento può diventare lento.

2.3 WebSocket — Chat Real-Time

Browser B
⇄

A differenza di HTTP (che è unidirezionale request-response), WebSocket mantiene una connessione persistente e bidirezionale. Il server può inviare messaggi ai client in qualsiasi momento senza che questi facciano una richiesta. Tutti i messaggi sono in formato JSON con i campi: type ("chat" o "system"), username, message, timestamp.

Il server WebSocket (wss) condivide la stessa porta 3000 del server HTTP grazie alla creazione di un server HTTP manuale con http.createServer(app) che viene passato sia a Express che a WebSocket.Server.

04 Middleware e Cookie

4.1 Middleware di Autenticazione

Il middleware è una funzione registrata con app.use() che viene eseguita per ogni richiesta, prima che raggiunga qualsiasi route handler:

javascriptserver.js
app.use((req, res, next) => {
    res.locals.currentUser = getUserFromCookies(req.headers.cookie);
    next();
});

res.locals.currentUser è un oggetto speciale di Express accessibile da tutti i template EJS come variabile locale. Se il cookie non esiste o non contiene user=..., il valore è null. Questo permette ai template di mostrare contenuti diversi per utenti loggati e non.

4.2 Gestione Cookie

Il sistema di autenticazione è basato su un singolo cookie HTTP:

OperazioneHeader HTTPEffetto
Login / SignupSet-Cookie: user=Lorenzo; Path=/Imposta il cookie con lo username encodato. Path=/ lo rende valido su tutto il sito.
LogoutSet-Cookie: user=; Path=/; Expires=Thu, 01 Jan 1970 00:00:00 GMTSovrascrive il cookie con una data nel passato: il browser lo cancella automaticamente.
LetturaCookie: user=Lorenzo (dal browser)Il middleware legge questo header e decodifica lo username con decodeURIComponent().

Lo username è codificato con encodeURIComponent() per gestire caratteri speciali (spazi, accenti, ecc.) nel nome utente. Il WebSocket legge lo stesso cookie dall'header HTTP della richiesta di handshake (req.headers.cookie), usando la stessa funzione helper getUserFromCookies().

05 Analisi Riga per Riga — server.js

Di seguito l'analisi completa e aggiornata del file server.js con il codice attuale del progetto.

Codice completo — server.js

javascriptserver.js
const express   = require("express");
const fs        = require("fs");
const path      = require("path");
const http      = require("http");
const WebSocket = require("ws");

const app    = express();
const server = http.createServer(app);
const wss    = new WebSocket.Server({ server });
const PORT   = 3000;

const usersFile = path.join(__dirname, "utenti.json");
const postsFile = path.join(__dirname, "posts.json");

app.use(express.static("public"));
app.use(express.urlencoded({ extended: true, limit: "10mb" }));
app.use(express.json({ limit: "10mb" }));
app.set("view engine", "ejs");

function getUserFromCookies(cookieHeader) {
    if (!cookieHeader) return null;
    const match = cookieHeader.split("; ").find(c => c.startsWith("user="));
    return match ? decodeURIComponent(match.split("=")[1]) : null;
}

function readJSONFile(filePath, defaultData = []) {
    try {
        if (!fs.existsSync(filePath)) return defaultData;
        const raw = fs.readFileSync(filePath, "utf8");
        return raw.trim() ? JSON.parse(raw) : defaultData;
    } catch (err) {
        console.error(`Errore lettura ${filePath}:`, err);
        return defaultData;
    }
}

function writeJSONFile(filePath, data) {
    try {
        fs.writeFileSync(filePath, JSON.stringify(data, null, 2));
        return true;
    } catch (err) {
        console.error(`Errore scrittura ${filePath}:`, err);
        return false;
    }
}

app.use((req, res, next) => {
    res.locals.currentUser = getUserFromCookies(req.headers.cookie);
    next();
});

app.get("/", (req, res) => {
    const posts = readJSONFile(postsFile, []);
    res.render("index", { posts });
});

app.get("/login",  (req, res) => res.render("login",  { error: null }));

app.post("/login", (req, res) => {
    const { username, password } = req.body;
    const users = readJSONFile(usersFile, []);
    const user  = users.find(u => u.username === username && u.password === password);
    if (!user) return res.render("login", { error: "Credenziali errate" });
    res.setHeader("Set-Cookie", `user=${encodeURIComponent(username)}; Path=/`);
    res.redirect("/");
});

app.get("/signup", (req, res) => res.render("signup", { error: null }));

app.post("/signup", (req, res) => {
    const { username, password } = req.body;
    const users = readJSONFile(usersFile, []);
    if (users.some(u => u.username === username))
        return res.render("signup", { error: "Username già in uso" });
    users.push({ username, password });
    if (!writeJSONFile(usersFile, users))
        return res.render("signup", { error: "Errore nella registrazione" });
    res.setHeader("Set-Cookie", `user=${encodeURIComponent(username)}; Path=/`);
    res.redirect("/");
});

app.get("/logout", (req, res) => {

app.post("/like/:index", (req, res) => {
    const user = res.locals.currentUser;
    if (!user) return res.json({ error: "Non autenticato" });
    const index = parseInt(req.params.index);
    const posts = readJSONFile(postsFile, []);
    if (index < 0 || index >= posts.length)
        return res.json({ error: "Post non trovato" });
    const post = posts[index];
    if (!post.likes) post.likes = [];
    const i     = post.likes.indexOf(user);
    const liked = i === -1;
    liked ? post.likes.push(user) : post.likes.splice(i, 1);
    writeJSONFile(postsFile, posts);
    res.json({ count: post.likes.length, liked });
});

app.post("/comment/:index", (req, res) => {
    const user = res.locals.currentUser;
    if (!user) return res.redirect("/login");
    const { text } = req.body;
    if (!text?.trim()) return res.redirect("/");
    const index = parseInt(req.params.index);
    const posts = readJSONFile(postsFile, []);
    if (index < 0 || index >= posts.length) return res.redirect("/");
    if (!posts[index].comments) posts[index].comments = [];
    posts[index].comments.push({
        author: user,
        text:   text.trim(),
        date:   new Date().toLocaleString()
    });
    writeJSONFile(postsFile, posts);
    res.redirect("/");
});

function broadcast(wss, payload, exclude = null) {
    const msg = JSON.stringify(payload);
    wss.clients.forEach(client => {
        if (client !== exclude && client.readyState === WebSocket.OPEN)
            client.send(msg);
    });
}

wss.on("connection", (ws, req) => {
    const username = getUserFromCookies(req.headers.cookie) || "Anonimo";

    ws.send(JSON.stringify({
        type:      "system",
        message:   `Benvenuto nella chat, ${username}!`,
        timestamp: new Date().toISOString()
    }));

    broadcast(wss, {
        type:      "system",
        message:   `${username} si è unito alla chat`,
        timestamp: new Date().toISOString()
    }, ws);

    ws.on("message", raw => {
        try {
            const data = JSON.parse(raw);
            if (data.type !== "chat") return;
            broadcast(wss, {
                type:      "chat",
                username,
                message:   data.message,
                timestamp: new Date().toISOString()
            });
        } catch (err) {
            console.error("Errore parsing messaggio WebSocket:", err);
        }
    });

    ws.on("close", () => {
        broadcast(wss, {
            type:      "system",
            message:   `${username} ha lasciato la chat`,
            timestamp: new Date().toISOString()
        });
    });

    ws.on("error", err => console.error("Errore WebSocket:", err));
});

11 Sicurezza e Note Tecniche

Misure di Sicurezza Presenti

  • Protezione route private — le route /post, /chat, e le POST di like/commento verificano res.locals.currentUser prima di procedere
  • Sanitizzazione HTML nella chat — la funzione escapeHtml() usa un nodo DOM temporaneo per convertire caratteri speciali HTML in entità sicure, prevenendo XSS
  • Validazione immagine — lato server si verifica che la stringa inizi con data:image/ prima di salvarla
  • Validazione testo commento — il server verifica con text?.trim() che il commento non sia vuoto o solo spazi
  • Limite dimensione body — Express è configurato con limit: "10mb" per prevenire richieste troppo grandi

Limitazioni di Sicurezza (per Uso Didattico)

  • Password salvate in chiaro — nessun hashing (in produzione: bcrypt, argon2)
  • Cookie senza httpOnly — accessibile da JavaScript, vulnerabile a XSS sulla pagina stessa
  • Cookie senza Secure — inviato anche su HTTP non cifrato
  • Cookie senza SameSite — potenzialmente vulnerabile a CSRF
  • Nessuna sessione server-side — impossibile invalidare sessioni lato server senza modificare il cookie
  • No rate limiting — possibili attacchi brute-force sul login
  • Testo commenti non sanitizzato nel template EJS — il <%= c.text %> in index.ejs non usa <%- raw ma <%= che effettua l'escaping EJS automatico
🔐
Attenzione per uso in produzioneQuesto progetto è pensato esclusivamente per scopi didattici. Prima di deployarlo su un server pubblico sarebbe necessario implementare: hashing password, HTTPS, session management sicuro, validazione input lato server, rate limiting.

Note sull'Indice dei Post

L'indice usato nelle route /like/:index e /comment/:index è la posizione del post nell'array di posts.json. Poiché i post vengono mostrati in ordine inverso sulla home, il template calcola l'indice reale con:

ejs
<% posts.slice().reverse().forEach((post, reversedIndex) => { %>
    <% const postIndex = posts.length - 1 - reversedIndex; %>

slice() crea una copia dell'array prima di invertirlo, per non modificare l'originale. reversedIndex è la posizione nell'array invertito; postIndex è la posizione nell'array originale, necessaria per le route di like e commento.

Funzione broadcast() — WebSocket

La funzione broadcast() è un helper introdotto nel codice aggiornato per evitare la duplicazione del ciclo wss.clients.forEach():

javascript
function broadcast(wss, payload, exclude = null) {
    const msg = JSON.stringify(payload);
    wss.clients.forEach(client => {
        if (client !== exclude && client.readyState === WebSocket.OPEN)
            client.send(msg);
    });
}

Il parametro exclude permette di escludere un client specifico dall'invio (usato al momento dell'ingresso per inviare solo agli altri utenti la notifica, mentre al nuovo utente si invia il benvenuto privato). readyState === WebSocket.OPEN verifica che il client sia ancora connesso prima di inviare.
