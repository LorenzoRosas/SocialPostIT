1. Introduzione

1.1 Obiettivi della Documentazione

Questa documentazione descrive il funzionamento completo del progetto Social PostIt, un'applicazione web realizzata con Node.js, Express.js, EJS e WebSocket. L'obiettivo è spiegare come è stato costruito il software, come gestisce dati come post e utenti salvati in file JSON, come sono state implementate le funzionalità di interazione sociale (like, commenti, allegati fotografici, chat in tempo reale) e come il progetto viene avviato e mantenuto.

1.2 Panoramica del Documento

Il documento è diviso in sezioni che coprono:

  • Architettura e organizzazione del software.
  • Scelte progettuali e di design.
  • Descrizione dettagliata di ogni funzionalità, comprese quelle aggiunte (upload foto, like, commenti, chat WebSocket).
  • Guida all'avvio e al deployment.
  • Documentazione riga per riga di ogni singolo file sorgente.

1.3 Descrizione del Software

"Social PostIt" è un'applicazione web che permette agli utenti di registrarsi, accedere, pubblicare post con titolo, testo e foto, mettere like, commentare i post altrui e comunicare in tempo reale tramite una chat live. Il server è costruito con Node.js e Express.js, le pagine sono dinamiche grazie al motore di template EJS, e la chat utilizza il protocollo WebSocket. I dati (utenti, post, like, commenti) sono salvati in semplici file JSON sul disco.

1.4 Scopo del Software

Il progetto dimostra come realizzare una piattaforma social completa senza l'uso di database relazionali complessi, sfruttando file JSON come storage leggero. È un progetto didattico che tocca concetti fondamentali dello sviluppo web: routing HTTP, autenticazione tramite cookie, comunicazione in tempo reale, gestione di file e rendering server-side.

2. Architettura del Software

2.1 Descrizione dell'Architettura

L'applicazione segue un'architettura server-side MVC (Model-View-Controller) semplificata. Il server Node.js con Express.js gestisce tutte le richieste HTTP (Controller), i file JSON fungono da modello dati (Model), e i template EJS generano le pagine HTML dinamiche (View). La chat aggiunge uno strato di comunicazione bidirezionale tramite WebSocket, che opera sulla stessa porta HTTP ma con un protocollo differente (ws://).

2.2 Componenti Principali

  • server.js: Cuore dell'applicazione. Gestisce tutte le route HTTP (GET/POST), il middleware per i cookie, le funzioni di lettura/scrittura JSON, le route per like e commenti, e il server WebSocket per la chat.
  • views/: Contiene i template EJS che Express renderizza in HTML dinamico. Include index.ejs, post.ejs, login.ejs, signup.ejs e chat.ejs.
  • public/: File statici serviti direttamente al browser. Contiene il GIF di sfondo animato.
  • utenti.json: Database semplificato degli utenti registrati (username e password).
  • posts.json: Database dei post pubblicati, con titolo, contenuto, autore, data, eventuale immagine in base64, array di like e array di commenti.

3. Analisi delle Priorità

3.1 Robustezza

3.1.1 Definizione

La robustezza è la capacità del software di funzionare correttamente anche in situazioni inaspettate: file JSON mancanti, dati malformati, richieste non autorizzate.

3.1.2 Aspetti Principali

  • Ogni lettura e scrittura di file JSON è protetta con blocchi try-catch per evitare crash del server.
  • Le funzioni readJSONFile e writeJSONFile gestiscono centralmente tutti i casi di errore (file inesistente, file vuoto, JSON corrotto).
  • Le route protette (/post, /chat, /like, /comment) verificano sempre l'autenticazione dell'utente prima di eseguire qualsiasi operazione.
  • Il campo image viene accettato solo se inizia con data:image/ per prevenire l'iniezione di dati arbitrari.
  • Il limite di 10MB sul body parser previene attacchi di tipo denial-of-service tramite upload di file enormi.

3.2 Usabilità

3.2.1 Definizione

L'usabilità misura quanto sia facile e intuitivo usare l'applicazione per un utente senza conoscenze tecniche.

3.2.2 Aspetti Principali

  • Layout visivo moderno con sfondo animato, palette di colori coerente (blu scuro, azzurro neon) e Bootstrap per la griglia responsiva.
  • Anteprima immediata dell'immagine selezionata prima della pubblicazione del post.
  • Like senza ricaricamento pagina (AJAX con fetch) per un'esperienza fluida.
  • Post visualizzati in ordine dal più recente al più vecchio.
  • Layout immagine + testo affiancati su desktop, in colonna su mobile.
  • Messaggi di errore chiari su ogni form (login, registrazione, creazione post).

3.3 Portabilità

3.3.1 Definizione

La portabilità indica la capacità del software di funzionare su sistemi diversi senza modifiche al codice.

3.3.2 Aspetti Principali

  • Funziona su qualsiasi sistema operativo dove è installato Node.js (Windows, macOS, Linux).
  • Non richiede database esterni. I file JSON sono portabili su qualsiasi file system.
  • L'uso di path.join() garantisce che i percorsi dei file funzionino correttamente su tutti i sistemi operativi.
  • Tutte le dipendenze sono elencate nel file package.json e installabili con un singolo comando npm install.

4. Design del Software

4.1 Principi di Design Adottati

  • Semplicità: ogni route ha una responsabilità chiara e limitata. Il codice è leggibile e commentato.
  • Separazione delle responsabilità: la logica server (server.js) è separata dalla presentazione (template EJS) e dai dati (file JSON).
  • Progressivo miglioramento: le funzionalità di base (leggere post) funzionano anche senza JavaScript abilitato. Like e chat richiedono JavaScript.
  • Compatibilità retroattiva: i post creati prima dell'aggiunta di like e commenti continuano a funzionare correttamente grazie ai fallback (post.likes || []).

4.2 Scelte Architetturali e Motivi

  • Node.js + Express.js: leggeri, veloci da configurare, ideali per progetti didattici di piccole-medie dimensioni.
  • EJS: sintassi semplice simile all'HTML, nessun concetto nuovo da imparare per chi conosce HTML.
  • File JSON: eliminano la necessità di configurare un database, rendendo il progetto avviabile con npm install + node server.js.
  • Cookie HTTP semplici: soluzione di autenticazione minimale senza librerie esterne.
  • Immagini in base64: evitano la gestione di upload su disco pur permettendo l'allegato di foto. Adatto per demo e piccoli progetti.
  • WebSocket nativo (libreria ws): protocollo standard per la comunicazione in tempo reale, integrato nel server HTTP esistente senza porte aggiuntive.
  • AJAX con fetch() per i like: evita il ricaricamento completo della pagina per un'azione semplice, migliorando l'esperienza utente.

5. Documentazione del Codice

5.1 Struttura del Codice Sorgente

  • server.js — File principale del server. Contiene tutto il codice Node.js/Express.js.
  • views/index.ejs — Pagina home: mostra tutti i post con like, commenti e layout immagine+testo.
  • views/post.ejs — Form per la creazione di nuovi post con upload immagine.
  • views/login.ejs — Form di accesso.
  • views/signup.ejs — Form di registrazione.
  • views/chat.ejs — Interfaccia chat in tempo reale con WebSocket.
  • public/background.gif — Immagine animata di sfondo.
  • posts.json — File di dati dei post.
  • utenti.json — File di dati degli utenti.

5.2 Route e Funzioni Principali

  • GET / — Carica e mostra tutti i post.
  • GET /login, POST /login — Visualizzazione e gestione del form di login.
  • GET /signup, POST /signup — Visualizzazione e gestione del form di registrazione.
  • GET /logout — Cancella il cookie e disconnette l'utente.
  • GET /post, POST /post — Visualizzazione e gestione della creazione post (con immagine opzionale).
  • POST /like/:index — Aggiunge o rimuove un like. Risponde con JSON per l'aggiornamento AJAX.
  • POST /comment/:index — Aggiunge un commento a un post.
  • GET /chat — Visualizzazione della pagina chat.
  • WebSocket (ws://) — Gestione messaggi in tempo reale, notifiche di ingresso/uscita dalla chat.

5.3 Funzionalità Aggiunte

Upload Immagine

L'utente seleziona un'immagine dal proprio dispositivo. JavaScript legge il file con FileReader e lo converte in una stringa base64, inserita in un campo hidden del form. Il server la salva nel JSON del post e al momento della visualizzazione la stringa base64 è usata direttamente come src dell'elemento <img>.

Like con Toggle

Il click sul cuore chiama toggleLike() via fetch() in background. Il server controlla se l'utente ha già messo like: in caso positivo lo rimuove, altrimenti lo aggiunge. Risponde con il nuovo conteggio e il browser aggiorna solo il bottone senza ricaricare la pagina.

Commenti

Un form sotto ogni post invia il testo a POST /comment/:index. Il server aggiunge il commento (autore, testo, data) all'array comments del post nel JSON. Solo gli utenti loggati vedono il form.

Chat in Tempo Reale

La pagina chat apre una connessione WebSocket persistente. Quando un utente invia un messaggio, il server lo riceve e lo ridistribuisce in broadcast a tutti i client connessi. Il server notifica anche gli ingressi e le uscite dalla chat con messaggi di sistema.

6. Testing

6.1 Strategia di Testing

  • Test funzionale delle route: verifica che ogni URL risponda con il contenuto corretto.
  • Test di autenticazione: verifica che le route protette reindirizzino al login se non autenticati.
  • Test upload immagine: verifica che immagini valide vengano salvate e visualizzate, e che file troppo grandi vengano rifiutati lato client.
  • Test like: verifica il toggle (aggiunta e rimozione) e che il conteggio si aggiorni correttamente.
  • Test commenti: verifica che i commenti vengano salvati e visualizzati correttamente.
  • Test chat WebSocket: apertura di due schede browser per verificare la ricezione dei messaggi in tempo reale.
  • Test portabilità: avvio del server su sistemi Windows e Linux per verificare che i percorsi file funzionino.

6.2 Risultati e Report

  • Tutte le route HTTP rispondono correttamente.
  • L'autenticazione tramite cookie funziona su tutte le pagine protette.
  • Le immagini fino a 5MB vengono caricate e visualizzate correttamente in base64.
  • Il sistema di like toglie e aggiunge correttamente, senza duplicati per lo stesso utente.
  • I commenti vengono salvati con autore, testo e data.
  • La chat funziona in tempo reale tra più client.
  • I post vecchi (senza likes/comments) vengono visualizzati senza errori grazie ai fallback || [].

7. Deployment e Portabilità

7.1 Guida al Deployment

Requisiti: Node.js versione 14 o superiore installato sul sistema.

Struttura cartelle richiesta:

/progetto ├── server.js ├── utenti.json ├── posts.json ├── views/ │ ├── index.ejs │ ├── post.ejs │ ├── login.ejs │ ├── signup.ejs │ └── chat.ejs └── public/ └── background.gif

Passi per l'avvio:

  • Passo 1: Aprire il terminale nella cartella del progetto.
  • Passo 2: Eseguire npm install per installare le dipendenze (express, ws).
  • Passo 3: Eseguire node server.js per avviare il server.
  • Passo 4: Aprire il browser e visitare http://localhost:3000.

7.2 Considerazioni sulla Portabilità

L'applicazione è completamente portabile su qualsiasi sistema con Node.js. Non richiede configurazioni esterne, database, variabili d'ambiente obbligatorie o servizi aggiuntivi. L'unica dipendenza esterna (oltre a Node.js) è la libreria ws per i WebSocket, inclusa nel package.json.

8. Manutenzione del Software

8.1 Strategie di Manutenzione e Bug Fixing

  • Monitoraggio file JSON: verificare periodicamente l'integrità dei file posts.json e utenti.json, specialmente se il server viene interrotto durante una scrittura.
  • Sicurezza password: in questa versione le password sono in chiaro. In una versione futura andrebbero hashate con bcrypt.
  • Crescita del file JSON: con molti post e immagini base64, il file posts.json può diventare molto grande. Soluzione futura: sostituire con un database o salvare le immagini come file separati.
  • Validazione input server-side: aggiungere controlli sul server per lunghezza massima di titolo, contenuto e commento.
  • Gestione sessioni: sostituire il cookie semplice con express-session o JWT per una gestione più sicura.
  • Rate limiting: aggiungere un limite alle richieste per evitare spam di like o commenti.

9. Conclusioni

9.1 Sintesi delle Proprietà Analizzate

  • Robustezza: gestione degli errori su tutti i file I/O, validazione dei dati in ingresso, protezione delle route con controlli di autenticazione.
  • Usabilità: interfaccia moderna e reattiva, like senza reload, anteprima immagini, layout adattivo, messaggi di errore chiari.
  • Portabilità: nessuna dipendenza da sistemi esterni, compatibile con tutti i sistemi operativi con Node.js, configurazione minima.

9.2 Suggerimenti Futuri per il Miglioramento

  • Sostituire i file JSON con un database (es. SQLite o MongoDB) per scalabilità e affidabilità.
  • Hashare le password con bcrypt per la sicurezza degli account.
  • Salvare le immagini come file nella cartella public/uploads/ anziché in base64 nel JSON.
  • Aggiungere la possibilità di eliminare i propri post.
  • Implementare un sistema di notifiche per i nuovi like e commenti.
  • Aggiungere paginazione per gestire molti post senza caricare tutto in una volta.

9.3 Lezioni Apprese durante lo Sviluppo

  • La modularità (funzioni helper readJSONFile e writeJSONFile) rende il codice più facile da mantenere e meno soggetto a errori.
  • I file JSON sono ottimi per prototipi e piccoli progetti, ma hanno limiti di scalabilità e sicurezza per le scritture concorrenti.
  • Il protocollo WebSocket permette comunicazione bidirezionale in tempo reale con poca complessità aggiuntiva rispetto a HTTP.
  • Convertire le immagini in base64 nel browser prima dell'invio elimina la necessità di gestire multipart/form-data e librerie di upload lato server.
  • L'uso di middleware Express centralizza operazioni trasversali come la lettura dei cookie, evitando codice ripetuto in ogni route.
